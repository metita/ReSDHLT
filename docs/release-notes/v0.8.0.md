RAD's largest remaining transfer-construction phase can now run on the GPU.

## GPU Sparse transfer factors

`-gpu` now accelerates both direct-light gathering and the construction of
Sparse patch transfer factors used by bounce lighting.

The old `MakeScales` path checked the full patches-squared space on the CPU. On
`ze_cardinal`, that meant 59,939 patches, 3.59 billion possible pair checks,
55.63 million stored transfers, and 58.43 seconds in `MakeScales` alone. The new
path walks only the pairs already present in the Sparse visibility matrix and
dispatches them to Vulkan in bounded batches.

The packed transfer format and CPU bounce accumulation are unchanged. A sealed
room parity test produced the same 95,742 transfers on CPU and GPU; the final
lighting differed in one byte out of 15,102, from 191 to 192.

`-gpu` falls back to the original CPU transfer path when Vulkan is unavailable,
the map uses RGB transfers, translucent patches, custom bounce shadows, or the
GPU dispatch fails. The console makes the selected path explicit:

```text
MakeScales (GPU: Radeon RX 560 Series, ... visible pairs):
```

## RAD diagnostics

- `-raybench` captures representative real sky rays and measures the BSP
  tracer directly. Optional Embree support can compare the same workload.
- `-workbench` measures per-face work and reports how much phase time comes
  from thread scheduling imbalance.

Both diagnostics are off by default and do not affect ordinary builds.

Full detail is in [CHANGELOG.md](https://github.com/metita/ReSDHLT/blob/main/CHANGELOG.md)
and the measurements in
[docs/BENCHMARKS.md](https://github.com/metita/ReSDHLT/blob/main/docs/BENCHMARKS.md).
