ReSDHLT 0.18.0 adds an optional way to subdivide faces that leaves fewer of
them to draw, makes RAD's bounces 2.4 times faster and lets the GUI copy the
map to the game and open it.

## Highlights

- New: `-gridsubdivide` in BSP ("Subdividir por celdas de luz" in the GUI).
  The engine takes a face that covers 16 lightmap cells or fewer; the classic
  rule cuts every 224 units without looking at the cells, so a 256 unit wall
  on the grid came out as 224 + 32. With the option BSP counts the cells the
  way the engine does and only cuts when it has to: 3% to 20% fewer faces on
  the maps measured (ze_sanctorum 5882 to 5256, ba_coliseum 815 to 655), with
  the same geometry and lighting. BSP counts again before it writes the file
  and stops with an error rather than leave a map that does not load. It is
  off by default and has not been checked in the game yet: try the map before
  you publish it.
- RAD: each bounce is 2.4 times faster and the CPU gather about 7% faster.
  fp_squidgame_thno went from 16.7 s to 14.6 s with the GPU and from 19.0 s to
  16.8 s on the CPU. BSP is about 17% faster on the same map.
- GUI: "Probar en el juego" in the Compilar tab copies the `.bsp` to
  `cstrike/maps` when a compile ends well, opens the game on the map, or both.
- GUI: the taskbar button asks for attention when a compile ends and the
  window is in the background.
- Fixed: running VIS twice on the same BSP output stopped with "Corrupted leaf
  mapping". The error now says to run BSP again first.

Without `-gridsubdivide` the tools write the same `.bsp` as 0.17.2, byte for
byte, on every map checked.
