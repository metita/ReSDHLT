ReSDHLT 0.22.2 makes the tools work when built with clang and catches a mistake
in the GUI's extra parameters. Compiled maps come out the same `.bsp` as in
0.22.1, so the Windows package only changes for the GUI's new check.

## Fixed

- RAD: builds made with clang at `-O2` or higher no longer stop on startup with
  "Compatability test failed". The check was right: packing an RGB transfer
  shifted a zero component by far more than the width of the value, and clang
  discarded the result.
- RAD: clang builds no longer light maps wrongly under
  `-rgbtransfers -rgbcompress 1` or `2`. They now match GCC and MSVC byte for
  byte.
- GUI: extra parameters that start with a bare word, like the tool's name in
  `hlcsg -hullfile giant.hull`, now block the compile with a clear message
  instead of stopping CSG with "Unknown option" on the real map path.
